v1.0.15 무선 CarPlay 기기 설정

USB 브리지 모드에서는 홈 → 폰 프로젝션 안내 팝업의 ‘설정’과
Bluetooth 설정의 무선 폰 프로젝션 메뉴가 순정 기기 연결 목록을 엽니다.
현재 브리지가 사용하는 Bluetooth 등록 기기를 이 화면에서 관리합니다.
부팅이나 CarPlay 연결만으로 이 화면을 자동으로 열지는 않습니다.

이 목록에서 기기를 삭제하면 Bluetooth 페어링도 함께 삭제됩니다.
CarPlay 등록만 지우고 Bluetooth 통화 등록을 유지하는 기능은 아닙니다.
삭제는 사용자가 순정 화면에서 선택하고 확인해야 하며, 패키지가
자동으로 기기를 삭제하거나 별도 unpair 명령을 실행하지 않습니다.

원래 무선 설정 목록은 WPP 등록 DB를 사용하지만, USB 브리지는
Bluetooth/iAP2 등록을 사용합니다. 두 목록이 다른 문제를 해결하려고
브리지가 실제 사용하는 순정 Bluetooth 관리 화면으로 연결합니다.
기기 목록은 Bluetooth 공용 목록이므로 CarPlay 기기만 필터링하지 않습니다.
순정 화면의 삭제 확인, 연결 처리와 운행 중 제한을 그대로 사용합니다.

브리지가 활성 상태가 아니거나 모드 자체가 비활성화되면 원래 설정 경로를 사용합니다. 공개 설정에 별도 브리지 스위치는 없으며 기본 동작으로 유지합니다.
유선 전용 설정 함수와 폰 프로젝션 설정 검색 진입은 변경하지 않습니다.
대상 화면이 없거나 실행에 실패하면 원래 설정 함수를 실행합니다.
음악·안내 음성·TBT·무선 연결·전원 처리에는 이 훅이 관여하지 않습니다.

구현과 검증
- 새 클래스: kr.ioniq5.usbcp.ProjectionSettings
- PhoneProjection의 정확한 팝업 Activity Context에서 들어온
  wireless.a.f.p(Context)와 BtSettings iP.aQ(Context)만 처리합니다.
- 대상: com.android.btsettings /
  com.android.settings2.bluetooth.DeviceConnectionSettingActivity
- 대상 ODEX 두 개를 펌웨어 해시로 고정하고 실제 APK의 system UID,
  Activity, action, 실제 메서드 선언 및 호출자를 확인했습니다.
- test_projection_settings.py: 실제 새 훅으로 호스트 19개 사례 통과.
- test_bridge_forget.py: 변경하지 않은 Bridge 메서드로 7개 사례 통과.
  BOND_NONE에서 해당 무선 세션·예약을 정리하고 iAP2 분리 이벤트를
  요청함을 확인했습니다. 차량의 native 세션 종료 완료를 재현하지는 않습니다.
- 별도 연구 검증: 대상 APK/ODEX 및 새 map에 대해 33개 검사 통과.

현재 ‘설정’ 버튼의 무응답 원인 자체는 정적 자료만으로 확정하지 못했습니다.
위 검증은 정확한 대상 코드와 호스트 실행 기준이며, 차량에서 설정 화면
진입과 삭제 이후 재등록은 별도로 확인해야 합니다. 설치 중에는 기기 등록을
자동으로 삭제하지 않습니다.
