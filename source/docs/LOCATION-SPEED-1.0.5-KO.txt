차량 GPS·차속 전달 — 1.0.5 수정 범위

확인한 순정 동작
정확한 한국 NEEV 260902 DiPO 코드에서 차량 GPS의 GPGGA/GPRMC는 새 GPS 시간의
NMEA 콜백이 오면 전달됩니다. 별도 위치 Listener 등록 요청 간격은 1초입니다.
차속은 MICOM 콜백이 km/h 정수로 전달되며 순정 코드가 m/s로 변환해 보관합니다.
차속·기어 관련 PASCD 문장은 별도 1초 타이머에서 만들어 iAP2로 보냅니다.
따라서 새 차속이 들어와도 다음 타이머까지 기다리는 구간이 존재합니다.

추가한 처리
실제 차속 콜백이 성공한 뒤 현재 차량 값을 사용하는 순정 PASCD 생성기를 요청합니다.
휴대전화가 PASCD를 요청했고 무선 CarPlay 세션이 활성화된 경우에만 동작합니다.
콜백 스레드에서 송신하지 않고 단일 작업 스레드에 한 건만 예약하며, 여러 변화가
들어오면 실행 시점의 최신 차량 값을 읽습니다. 추가 송신은 최소250ms 간격입니다.
순정의 1초 주기 송신은 그대로 유지합니다. 보조 송신이 실패하면 해당 요청에서는
보조 처리를 중단하고 다음 정상 위치 요청부터 다시 시도합니다.
요청 종료·세션 변경·비활성화 뒤 대기 중인 전송은 중단합니다. 이미 수락된 IPC 호출을
나중에 취소할 수는 없으며, 실행 중인 호출이 끝난 뒤 새 요청으로 넘겨 보내지 않습니다.

GPS 위치나 차속을 예측·보간하거나 새 값으로 바꾸지 않습니다. 단위·기어·시간·체크섬은
순정 생성기를 그대로 사용하고 GPS 수신 주기나 센서 등록 조건도 변경하지 않습니다.
차속 빠른 전달 설정을 끄면 순정 경로만 남습니다. 유선 CarPlay에는 적용하지 않습니다.

확인 한계
이 수정은 차속 전송의 최대 한 주기 대기 요소를 줄이는 것입니다. 아이폰이 어떤 입력을
선택하고 내비 앱이 필터링·화면 표시하는 데 걸리는 시간은 차량 코드만으로 결정할 수
없습니다. GPS 수신 자체의 지연이나 지도 화면의 모든 지연이 해결됐다고 보장하지 않습니다.
현재 GPS NMEA 경로에는 입증된 추가 대기열이 없어 임의로 교체하지 않았습니다.
호스트 시험은 병합·주기·요청 종료·실패 처리를 검증하며 실제 차량 표시 지연은 별도
시험이 필요합니다. 수집 기록의 source/send 간격과 max_binder_ms를 함께 확인합니다.
