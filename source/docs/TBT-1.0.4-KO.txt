v1.0.4 CarPlay·Android Auto 계기판·HUD 안내 변경

차선 안내
- 순정 내비가 휴대전화의 차선 표시를 다시 덮지 않도록, 활성화한 CarPlay 또는
  Android Auto의 길안내 중에 순정 내비 프로세스의 두 차선 출력 함수를 양보시킵니다.
  CarPlay·Android Auto 자체 출력과 제한속도·카메라 경고 출력 함수는 대상이 아닙니다.
  안내 종료 또는 기능/패키지 비활성화 후에는 원래 차선 출력이 통과합니다.
- 먼저 도착한 차선 정보를 버리지 않고 component와 LaneGuidanceIndex별로
  보관합니다. route의 현재 차선 안내 번호를 우선하며, 그것이 없으면 현재
  maneuver의 linkedLaneGuidance 번호를 사용합니다. 선택된 번호와 다른
  미래 차선 안내가 현재 화면을 덮지 않도록 했습니다.
- route item17은 도로의 차선 개수가 아니라 전체 차선 안내 레코드 수입니다.
  이를 물리적 차선 수로 사용하지 않습니다. 안내 번호0과 8번째 차선도 보존합니다.
- route item18은 휴대전화 앱 화면의 표시 상태이므로, false만으로 계기판에서
  차선을 숨기지 않습니다. 명시적 안내 개수0·빈 차선 목록은 표시를 지웁니다.
- 종료·소스 앱 변경·연결 종료·순정 내비 표시권한 전환 시 이전 차선 캐시가
  다음 안내에 재사용되지 않게 했습니다. component당 최대32개 기록을 보관하고
  현재 선택된 기록은 상한 정리에서 유지합니다.
- 모든 component 정보보다 먼저 온, component도 없는 차선 패킷은 수신 대상을
  추측하지 않습니다. 차선 내 불완전한 항목은 물리적 위치를 유지합니다.
  사진의 오른쪽 여백을 임의로 두 차선 삭제하는 방식으로 처리하지 않습니다.

추천 화살표
- 한국 r8.2 패키지의 실제 smali에서 확인한 raw81 phone-lane 형식은 차선 전체
  상태 하나가 아니라 두 개의 2비트 화살표 스타일을 사용합니다. 세 번째 화살표는
  두 번째 스타일을 공유하므로 필요한 경우 같은 스타일끼리 화살표 순서만 묶습니다.
  도로의 좌우 차선 순서는 바꾸지 않습니다.
- 추천2는 명시적으로 받은 primary/highlight 각도에만 적용합니다. status1 또는
  status2 숫자만 보고 방향을 고르지 않습니다. 나머지는 r8.2에서 확인한 normal1,
  원시 status0인 경우 unavailable3 스타일을 사용합니다.
- primary가 secondary 목록에 포함되지 않는 Apple SDK 계약을 계속 지킵니다.
  primary-only 방향을 잃지 않으며, 중복·무효 각도는 추가 빈 화살표로 만들지 않습니다.
- 스타일2가 실제 차량에서 어떤 색·강조로 보이는지와 오른쪽 여백이 사라지는지는
  차량에서 확인해야 합니다. 송신 바이트 일치가 표시 결과 검증을 대신하지 않습니다.

순정 형식 턴 표시
- 설정: carplay_standard_turns / ‘CarPlay 순정 형식 턴 표시’, 기본 켜짐.
  변경 적용에는 인포테인먼트 재시작이 필요합니다. 끄면 기존 projection 형식을 씁니다.
- iAP2의 실제 미터 거리와 maneuver 종류·선택각이 확인될 때, 457m 이내에서
  순정 타입13(방향),31(유턴),17/18(좌우 진출),32/33(회전교차로)과 방향·거리 바를
  보냅니다. 명시적 도착 상태는 도착 타입3을 사용합니다.
- 한국 r8.2의 CP 타입 변환과 PR75의 거리 바 형식을 근거로 독립 구현했습니다.
  Android Auto의 이벤트 번호를 CarPlay 번호로 취급하지 않습니다.
- 잘못된 방향·각도 조합, 미확인 유형, 먼 거리, 원시 미터가 없는 표시 문자열은
  기존 아이콘으로 돌아갑니다. 문자열 거리 자체는 이전처럼 표시할 수 있습니다.
- HUD의 F2 목록은 기존 projection 아이콘을 유지합니다. 음악·음성 안내 채널,
  거리 값과 목적지 남은 거리의 1초 갱신 제한은 변경하지 않았습니다.
- 이 기능은 한국 NEEV 260902의 화면 표현을 아직 실차 검증하지 않은 후보입니다.
  ‘AR 화면이 검증됐다’는 뜻이 아닙니다. 터널 전용 OEM 아이콘 번호는 확인하지
  못해 기존의 휴대전화 터널 안내 문구 보존 범위를 유지합니다.

Android Auto 안내와 USB 구분
- AA의 회전·거리·도로명·차선·이후 회전·목적지·남은 거리·도착시각을 계기판과
  HUD로 전달하는 어댑터를 추가했습니다. 휴대전화가 보내지 않은 정보를 생성하지는
  않습니다. 이미 순정 AA TBT를 사용하는 stepofspec 999 이상 구성은 그대로 둡니다.
- aa_tbt는 기본 켜짐이며 aa_standard_turns는 기본 꺼짐입니다. AA의 선택형 순정
  형식은 AA 이벤트의 의미로 변환합니다. 457m 안내 범위와 거리 막대, 가까운 도착
  표시를 사용하고 HUD 목록은 projection 아이콘을 유지합니다. 한국 차량의 실제
  화면은 확인 전이며 CarPlay의 번호 체계와 혼용하지 않습니다.
- 대상 라이브러리 전체 해시와 레시피의 바이트 조건을 확인합니다. HMG-API가 이
  모드의 해당 레시피를 실제 적용했다는 소유 기록이 확인돼야 ENUM 안내를 요청합니다.
  패치 요청 호출만 성공했다고 적용 완료로 간주하지 않습니다. 인터페이스가 없거나
  라이브러리·소유 기록이 맞지 않으면 AA TBT 훅은 원래 안내 형식을 유지합니다.
- 수신 작업은 하나의 제한된 큐에서 처리합니다. 수신 객체와 세대가 다른 늦은
  콜백을 버리고, 연결 초기화의 성공을 확인한 뒤 표시합니다. 순정 내비가 표시권한을
  받으면 표시를 지우지 않고 내부 상태만 버립니다. active 상태만으로 순정 표시권한을
  다시 가져오지 않으며 휴대전화 표시권한 복귀도 확인합니다. CarPlay가 안내 중이면
  AA 출력은 양보합니다. 두 프로젝션의 동시 연결 안정성을 보장하는 기능은 아닙니다.
- 종료·표시권한 전환 뒤 이전 거리·HUD 중복 제거 상태·차선·이후 회전을 재사용하지
  않습니다. 사용하지 않는 타이머를 멈추고 실패한 초기화나 종료된 세션은 복구하지 않습니다.
- aa_usb_drives는 기본 켜짐입니다. AA 유선 시작 요청에 실린 USB 장치의 인터페이스가
  모두 저장장치 또는 허브일 때만 해당 요청을 막습니다. 복합 휴대전화, 무선 시작,
  알 수 없는 장치와 다른 서비스 요청은 원래대로 처리합니다. TBT 적용 여부와 독립입니다.
- 이 TBT/USB 구분 코드만으로 외부 Wi-Fi 자격 정보가 전달되거나 무선 AA 연결이
  만들어지는 것은 아닙니다. 추가 맵의 실차 검증이 끝나지 않은 외부 AP 연결 어댑터는
  이번 설치용 core에 포함하지 않으며 별도 실험 소스로 보관합니다. 기존에 AA 연결을
  제공하는 구성과 TBT 표시의 정상 동작은 각각 확인해야 합니다.

검증과 근거
- tests/test_native_lanes.py: CP/AA 표시권한·종료·비활성화32개 사례 통과.
- tests/test_lanes.py: 바이트/화살표27개, 이벤트·캐시 수명주기30개 검사 통과.
- tests/test_maneuvers.py: 기존 거리·턴·문자열·목적지 갱신 회귀검사와 신규 표준형식
  60개 검사 통과. 기본 형식의 송신 tuple도 유지됨을 확인했습니다.
- tests/test_aa.py는 실제 AA 표시 코드53개와 훅·수명주기109개 호스트 검사를
  통과했습니다. 세션 교체,
  순정 내비·CarPlay 표시권한, 초기화 실패, 늦은 콜백, 큐 상한, USB 장치 분류와
  패치 소유 확인을 검사합니다. 대상 차량의 기존 보고서에는 훅 선언 일치가 있지만
  현재 작업 환경에는 정확한 GPM ODEX·AA 원본 라이브러리가 없어 해당 바이너리를
  직접 실행·역분석한 검증으로 표현하지 않습니다. 설치 시 해시·맵 검증과 런타임
  패치 조건을 통과해야 하며 실차의 AA 연결 및 화면 확인이 남아 있습니다.
- 연구용 exact-smali 대조: 선택 가능한 CP 표준형식4,688조합, 화살표/스타일9,600조합이
  한국 r8.2의 해당 순수 함수 출력과 일치합니다. 캡처·복원 DEX 및 smali 해시를 고정하고
  JADX의 추정 Java 대신 실제 분기·정수·배열 명령을 실행하는 제한된 검증기를 사용했습니다.
- 원본 APK/DEX나 디컴파일한 전체 helper는 배포 소스에 포함하지 않습니다.
  r8.2 자료는 사용자가 제공한 GPL-3.0 계열 한국 포팅 패키지이며, wire 형식 사실을
  확인하는 참고 자료로 사용했습니다. 새 helper 코드는 이 프로젝트 안에서 독립 작성했습니다.
- 공개 상위 변경: https://github.com/VysseCodes/HMG-API/pull/75
  Apple SDK: CPLane, CPLaneGuidance, CPManeuver.linkedLaneGuidance, CPNavigationSession.currentLaneGuidance.
