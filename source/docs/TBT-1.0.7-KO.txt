1.0.7 TBT 세밀한 진행 입력 — 구현·실차 확인 범위

정확한 차량 코드에서 확인한 전달 경로
- 순정 Navi의 main TBT는 10% 단계, trap TBT는 별도의 0..100 진행값을 보냅니다.
- 해당 0..100 값은 NaviTbtTrapInfo.barGraphLevel이며, service는 trap packet의 8번 byte로 그대로 전달합니다.
- main의 0값은 오류 코드가 아닙니다. invalid/미표시는 별도 barGraphErr로 구분됩니다.
- 순정 내비의 거리→진행률 계산과 회전 통과 전이는 native 엔진에서 만들어지므로 Java 전달 코드만으로 확정하지 못했습니다.

1.0.7의 구현 목적
기존 10..90 단계만 보내던 경로에서 누락된 세밀한 진행 입력과 유효한 0m 끝점을 전달합니다.
새 회전·길안내 종료·거리 유효성·프로젝션 소유권을 확인하며, 카메라·제한속도 등 다른 trap 정보를 유지합니다.
유효한 거리가 기존 457m 구간 안에 있으면 ceil(100 × 미터 / 457)을 0..100으로 제한하여
main과 trap에 같은 진행률을 보냅니다. main은 차량 service가 다시 10% 단계로 양자화합니다.
양수 거리는 최소 1이며, 실제 유효한 0m에서만 0이 됩니다. 이 수식의 457m 구간과 감소 방향은
기존 구현을 따른 선택입니다. 순정 native 엔진에서 복원한 정확한 수식이라고 주장하지 않습니다.
카메라·제한속도를 포함한 22개 필드를 보존하고, 갱신에는 2초 이내의 순정 trap 정보를 사용합니다.
추가 재전송은 최대 초당 5회로 제한하며, 기존 순정 콜백의 전송 주기는 유지합니다. 새 회전은 모양이 같아도 새 소유권으로 구분합니다.
약 500ms의 소유권 갱신은 진행률의 유효성을 유지하기 위한 것입니다. 시간만으로 가상의 차량
위치를 전진시키거나, 임의의 회전 통과 상태를 만들지 않습니다. 명시적으로 유효하지 않은 원시 거리나
빈 거리 문자열이 오면 이전 진행률을 유지하지 않습니다.

확인 필요
- 보내는 진행률과 실제 계기판/HUD 커서의 움직임이 일치하는지
- 마지막 회전 접근과 통과 후 새 회전 표시가 이어지는지
- 순정 카메라·제한속도·경고가 계속 유지되는지
- raw 미터와 앱의 반올림된 표시 거리 경로의 차이

기존 거리 검증·아이콘·차선·문자열 동작은 이전 버전 문서를 참고하세요.
TBT-1.0.6-KO.txt의 10..90 최솟값 유지 설명은 1.0.6에 관한 이력이며, 1.0.7 진행 채널 변경과 구분합니다.
이 문서는 코드 전달 범위를 설명하며 실제 순정과 동일한 애니메이션 완료를 보장하지 않습니다.
