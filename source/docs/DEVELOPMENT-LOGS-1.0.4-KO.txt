개발용 상시 기록과 화면 오류 재요청 — CarPlay 1.0.4

USB 메모리가 없어도 설치된 development-log 서비스가 이 모드의 HMG-API 기록을
차량 내부 /data/nemesis/neev-usbcp-logs/development 에 보관합니다.
2 MiB 파일 4개(현재 파일과 이전 3개), 총 8 MiB로 순환합니다. 재부팅해도 기존 파일은
남으며 여유 공간이 64 MiB보다 적으면 새 기록을 건너뜁니다. 무제한 이력은 아닙니다.
다른 앱 전체 로그나 영상 프레임은 수집하지 않습니다. 기존 AP 원시 로그까지
이 용량 제한으로 바뀌는 것은 아닙니다.

기록 내용
- 세션 시작·종료, 화면 표시/숨김, 화면 Activity와 Surface 수명, 디코더 오류/타임아웃
- 활성 세션의 10초 단위 집계, 기존 오디오·위치 전송 집계 및 전원 종료·복귀
- 프로세스 PID, 시간과 기록기 시작 표식으로 재시작 전후 구분
Surface 유효/Activity 재개 기록은 실제 영상 프레임이 계속 바뀐다는 증거가 아닙니다.
갑작스러운 전원 손실, 순환 덮어쓰기, 긴 행 제거로 최근 기록 일부가 없을 수 있습니다.

화면 오류 시 재요청
정확한 NEEV 260902에서 확인한 키 프레임 요청 함수를 사용합니다.
활성 무선 세션의 특정 디코더 오류(1~3)나 화면 타임아웃에서만 비동기로 요청합니다.
최소 2초 간격, 대기 1개와 실행 1개로 제한합니다. 일정 간격의 강제 재요청이나
화면 숨김/표시 반복은 하지 않습니다. 네이티브 반환 성공이 화면 복구 성공을 뜻하지는
않습니다. 오류 콜백 없이 화면만 멈추는 경우는 기록을 보고 원인을 더 확인해야 합니다.

USB로 가져오기
자동 실행 USB에서는 파일을 바꿀 필요가 없습니다. 설치된 같은 1.0.4의 테스트를 마친 뒤
동글 대신 설치 USB를 꽂고 NEMESIS 실행 팝업에서 Yes를 누릅니다. 정상 설치 상태를
확인하면 재설치하지 않고 NEEV_BUNDLE_RESULT_... 폴더에 기록을 내보냅니다.
저장 완료 알림 뒤 USB를 Mac으로 가져옵니다. 문제 발생 시각도 함께 메모해 두세요.
USB_AUTO_RESULT_... 폴더에는 설치/수집 분류와 실행 결과가 남습니다.
미설치 또는 지원하는 이전 버전이면 같은 실행 동의로 CarPlay 설치/업데이트를 진행합니다.
같은 버전의 손상·불완전 상태나 알 수 없는 버전은 오류를 표시하고 자동 재설치하지 않습니다.
명시적 복구 표시파일은 자동 모드에서 사용하지 않습니다.

자동 실행이 아닌 예전 수동 설치 목록 USB는 기존처럼 기록수집용/NEMESIS.data를
루트에 덮어써서 수집할 수 있습니다. 새 자동 실행 USB에는 이 교체가 필요 없습니다.
development-current.txt와 development-1/2/3.txt에 보관된 기록을 내보내며,
development-status.txt에 없는 파일·읽기 제한 등의 결과를 남깁니다.
USB 내보내기는 고정된 이벤트와 숫자 필드만 재구성하고 도로명·SSID·전화기 식별자 등은
복사하지 않습니다. 전원 이벤트, 위치 집계, 오디오 집계는 같은 결과 폴더의 기록도 확인합니다.
일반 기록 수집은 펌웨어 APK/ODEX 파일을 자동 복사하지 않습니다.

이번 구현은 코드 및 호스트 시험을 통과했으며 차량에서 로그 지속성과 복구 여부는
아직 확인 전입니다. 실패 시 NAV→CarPlay로 돌아왔던 시각을 기록과 함께 비교합니다.
