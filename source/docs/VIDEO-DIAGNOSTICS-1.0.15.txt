1.0.15 영상 정지 추가 기록

목적
CarPlay 화면이 정지했지만 화면 오류 콜백이 발생하지 않는 경우를 더 잘 구분한다.
주기적으로 화면을 강제 재부착하지 않으며 기존 오류/timeout 기반 복구는 유지한다.
이 버전도 표시 프레임 수를 확인하는 구현은 아니다. 수신/디코딩/실제 표시 단계 중
어느 단계에서 정지했는지 이 추가 기록만으로 모두 구분할 수 있다고 주장하지 않는다.

확인한 순정 인터페이스
대상 HKMC_DiPO의 CarPlayService와 ICarPlayListener/ICarPlayServiceListener에는
onScreenStarted/Stopped/Timeout, onNotifyDecodeFailure, onSetSurfaceRequired가 있다.
Java에서 읽을 수 있는 디코드/표시 프레임 카운터나 프레임 완료 콜백은 확인하지 못했다.
native library에 ProcessFrames/DecodeScreenStream/DisplayScreenStream 기호는 있으나
이름만으로 호출 규약과 성공한 표시 의미를 알 수 없어 추정 native hook을 추가하지 않았다.

추가된 USB_CP_VIDEO window 항목 — 기존 10초 집계에 포함
surface_valid_now:
  마지막 showDisplay가 성공한 Surface의 현재 isValid() 결과. -1은 확인할 객체 없음.
  기존 surface_valid는 마지막 생명주기 콜백 상태다. 유효 Surface도 영상이 정지할 수 있다.
last_event_age_ms / screen_event_age_ms / decode_age_ms:
  마지막 관측 이벤트·화면 시작/정지/timeout·디코드 오류가 발생한 후 경과시간.
  마지막 오류코드가 새 오류인 것처럼 반복 해석되지 않도록 구분한다. -1은 미관측.
iap_control / control_bytes / control_age_ms:
  실제 CarPlay 객체의 oniAPSendMessage 콜백 수, 검증된 길이 합, 마지막 완료 후 시간.
  제어 데이터의 길이만 읽고 원시 내용은 복사하거나 로그로 쓰지 않는다.
  영상 패킷이나 표시 프레임 수가 아니다. observers_ready에 control_is_video=0을 명시한다.
hook_path_max_ms / hook_path_kind:
  관측 before→after 경로의 가장 긴 실행시간과 해당 종류. 다른 hook/순정 본문 시간을
  함께 포함할 수 있으므로 순정 JNI 실행시간 단독 수치가 아니다. 0ms이면 종류 -1일 수 있다.
inflight_tracked / inflight_oldest_ms / inflight_kind_mask / inflight_overflow:
  before를 지났지만 after가 끝나지 않은 호출을 최대 32개까지 추적한다.
  가장 오래된 호출의 시간, 해당 종류의 비트마스크, 이번 창의 추적 초과 수를 기록한다.
  초과 시 원래 호출은 정상 진행하며 추가 추적만 생략한다. 전체 호출 수 상한이라는 뜻은 아니다.
worker_late_ms:
  영상 진단 worker의 예약 시각보다 늦게 실행된 시간.
main_pending_age_ms / main_ack_age_ms / main_lag_max_ms / main_post_failed:
  별도의 가벼운 main looper 응답 확인. 최대 한 개만 대기하므로 main이 멈춰도 큐가 쌓이지 않는다.
  main_pending은 미응답 경과시간, main_ack는 마지막 응답 경과시간, main_lag_max는
  이번 창에 응답한 작업의 가장 긴 대기시간이다. post_failed는 예약 실패 횟수다.
  멈춘 session의 늦은 응답은 새 session을 정상으로 표시하지 않는다.

kind 번호 및 inflight_kind_mask 비트 위치
0 screen_started, 1 screen_stopped, 2 screen_timeout, 3 decode_failure,
4 mode_changed, 5 show_display, 6 hide_display, 7 activity_resume,
8 activity_pause, 9 surface_created, 10 surface_changed, 11 surface_destroyed,
12 iap_control.

부하와 보관
제어 데이터 콜백별로 로그를 출력하지 않는다. 기존 상세 영상 기록은 10초당 최대 12개다.
집계는 별도 worker에서 10초마다 1행. main 확인은 같은 주기이며 대기는 최대 1개다.
목적지·좌표·패킷 내용·예외 메시지·Surface 문자열·화면 픽셀을 새 기록에 넣지 않는다.
DevelopmentLogger가 기존 2MiB 파일과 회전 3개에 보관하고 같은 버전 USB 수집에 포함한다.
새 collector나 네트워크 통신, 차량 전원 변경, 강제 화면 전환은 추가하지 않는다.

검증
test_video.py: 실제 hook adapter를 실행하는 host fixture 155개 검사 통과.
오래된 session 응답, 20초 main 미응답, worker 지연, 현재 Surface 무효화,
13.2초 실행 중 호출, 중첩 41개 호출의 32개 추적 제한, payload 불변과 로그 제한을 검증했다.
test_video_recovery.py: 기존 복구 회귀 fixture 252개 검사 통과. 복구 코드는 변경하지 않았다.
host 결과이며 실제 차량 프레임 복구 성공 검증은 아니다.
