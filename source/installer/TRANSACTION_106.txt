The 1.0.5 wrapper-only USB shell compatibility fix did not change the signed kit/mod
pair. The complete pinned old kit and old mod signature are checked before accepting
1.0.5 as an update source. The installed mod is independently verified before backup.
No old installer script is executed. Arbitrary same-version bytes are rejected.

Preserved sources: both released 1.0.4 kit/mod pairs, final signed 1.0.3, map-repair
1.0.2, original 1.0.1, legacy 0.1.10/0.1.11, and fresh installation. The accepted
1.0.4 pairs cannot be mixed. No old release archive or transaction is rewritten.

Update keeps existing AP identity, configuration and HMG settings. A failed update
restores the exact source mod, original map and map-check receipt under the existing
transaction rules. An interrupted install is recovered before retrying. The exact
missing-target-map error alone permits reconstruction; unrelated errors do not.

Completed manual uninstall, including after rollback, permits a fresh installation.
Only an authenticated completed old workspace is parked in a unique removed archive;
unknown, changed or incomplete workspaces stop instead of being deleted. Existing
settings are parked with that workspace. Fresh installation requires the vendor input
on USB. Independent mute-pause and startup packages are neither installed nor checked.

USB_AUTO.sh installs 1.0.6 when missing, updates supported older versions, and exports
logs only when the exact 1.0.6 installation is healthy. It never silently reinstalls
a damaged same-version installation. The Android shell compatibility fix uses strict
single-line validation plus echo, with no dependency on a printf command. Explicit
recovery remains a separate manual operation with a zero-byte NEEV-CP-RESTORE marker.

New host regression module test_upgrade_106.py reads the immutable real 1.0.5 ZIP
and validates its archive and member hashes. Cases cover update/rerun/rollback,
manual uninstall, rollback then uninstall, config/mute preservation, incomplete or
unknown state, damaged kit/mod, install/map failures, interrupted install recovery,
and missing-map repair. Existing 1.0.4 and older regression suites remain included.
These tests model NEMESIS/Android engine effects. They do not prove live firmware,
wireless transport, or signature engine execution on the vehicle.

Feature scope for 1.0.6: screen recovery, AR turn-distance guards and evidence logging.
This release does not claim to solve every AR HUD behavior, GPS delay, tunnel icon,
or USB 5 V shutdown. Details are in the release feature/change documents.
