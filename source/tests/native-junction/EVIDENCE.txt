Why width-dependent two-branch patterns are intentionally omitted
DetermineDifferLane at0x29f22ae chooses true only when the straight branch
has strictly more lanes. CarPlay item10/11 describes road bearings, not the
two road lane counts. Missing lane counts do not establish equal widths.
Therefore this helper never chooses guide1/4/7/10 from a fabricated flag.
It supports the two lane-independent guide23 cases and complete three-way
L/S/R topology. The ordinary maneuver remains available outside this helper.

Payload ABI
FrameCluster::SetPatternData0x26279ec and sendPatternData0x2629668 produce
five values: guidePatternIndex, arrowPatternIndex0, arrowPatternIndex1,
patternGuideLaneBits, patternGuideColor. The arrays emitted here are
{guide,arrow0,65535,0,0}: no second arrow, no supplied lane/color metadata.
This helper does not claim that the receiving renderer displays a template
merely because transport accepts its IDs. Caller owns enable/mode, deduplication,
explicit clearing, guidance lifecycle, and avoiding stale state.

Angle evidence and deliberate conservative policy
DetermineDirByAngle0x29f4624 classifies native unsigned bearings:
  0..5 and355..359: straight category
  6..20: keep right
  340..354: keep left
  21..179: right category
  181..339: left category
  180: unknown category
Keep-left/right are resolved relative to the other branch and can become
straight or side. This helper does not approximate that logic; magnitude6..20
is rejected. Its accepted straight range is[-5,5].
The native side category extends to179 degrees. The helper applies a separate
conservative rejection at magnitude>=158 (the existing CpTurns U-turn gate),
so near-back geometry never requests a fork template. This158 boundary is an
implementation acceptance policy, NOT an asserted native classification rule.

CP integration contract
pattern(maneuverType,junctionType,selectedAngle,otherAngles) accepts only ordinary
junctionType0, an explicit bounded item11 selected angle, and exactly one or two
item10 other arms. Inputs may use[-360,360] like CpTurns.selectedAngle; only one
revolution is normalized. Other arms must exclude the selected road. Duplicate
normalized bearings and multiple branches in the same side class are rejected,
not deduplicated, because collapsing them would invent a simpler topology.
Three outgoing branches must have exactly one left, straight, and right arm.
No incoming/back-facing arm is silently dropped. Unknown, U-turn, roundabout,
arrival and unsupported maneuver types are rejected. Known directional types
must agree with selected geometry; neutral follow-road/ramp/change-highway
types rely on the explicit geometry. Maneuver type interpretation follows the
existing CpTurns iAP2 mapping, independently of Android Auto enums.

Executable validation
  python3 tests/test_native_junction.py
Compiles the actual production helper as Java8, then checks native tuples,
permutations, signed/wrapped bearings, category boundaries, duplicate roads,
ambiguous geometry, absent lane counts, bounded input, excluded maneuver types,
contradictory types, output ownership, and left/right reflection properties.
These tests validate selection behavior, not the vehicle's visible rendering.
